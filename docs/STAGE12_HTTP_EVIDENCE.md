# 12단계 제작 2 — 1~11단계 실측 점검표 절차

## 목적과 구분

탈환 작전실의 표는 단계별 **정상/금지 요청, 기대 결과, 실제 HTTP 응답, 요청 ID, 확인 시각**을 함께 기록합니다. 최초 상태는 모두 **미실행**입니다. 같은 화면의 판정기 규칙 수 5개는 *규칙 등록 수*이지 실제 공격 방어 수가 아닙니다.

**공식 41종 총공세와 분리:** 아래 읽기 전용 5건은 41종 공격 시험이 아닙니다. 41종 개별 결과·실행 여부를 확인할 공식 증거가 없다면 41건을 통과로 표시하지 않습니다. 공개 자료실의 실제 요청과 로컬 가상 검사, 제공 엔진이 집행한 회수는 각각 출처가 다릅니다.

## 실제 운영 HTTP 5건 실행

1. Vercel 배포 후 **기존에 로그인하고 기기 승인을 받은 시험 계정의 같은 브라우저**로 `/operations.html`에 접속합니다. `GET /api/operations`가 HTTP 200인지 화면과 DevTools → Network에서 확인합니다.
2. 화면의 **「안전한 HTTP 실측 5건 실행」** 버튼을 눌러, 다음 GET만 수행합니다. 메모 추가·수정·삭제, 승인 요청, 회수, 복구는 수행하지 않습니다.

   | 단계 | 유형 | 호출 | 기대 HTTP | 응답 데이터 사용 |
   |---|---|---|---|---|
   | 1 | 금지 | 비인증 `GET /data.json` | 404 | 상태만 사용 |
   | 2 | 정상 | 승인 쿠키 `GET /api/notes` | 200 | **본문 미열람** |
   | 2 | 금지 | 쿠키 제외 `GET /api/notes` | 401 | **본문 미열람** |
   | 11 | 정상 | 승인 쿠키 `GET /api/operations` | 200 | 상태·헤더만 사용 |
   | 11 | 금지 | 쿠키 제외 `GET /api/operations` | 401 | 상태·헤더만 사용 |

3. DevTools → Network에서 `notes`와 `operations` 요청을 열어 **HTTP 상태**, Request Headers의 `X-BB-Check-ID`, Response Headers의 `X-Request-ID` 및 `X-Observed-At`을 확인합니다. 서버가 발급한 요청 ID·시각을 우선 기록합니다. 이 헤더가 없는 API 응답은 HTTP 상태가 일치해도 **확인 필요**로 남깁니다. `/data.json`은 서버 ID 헤더가 없어 브라우저가 요청에 넣은 `X-BB-Check-ID`와 브라우저 시각을 **출처 구분하여** 사용합니다.
4. 표에서 정상 HTTP 200과 금지 HTTP 401이 **각각 실제로 관측되었는지** 확인합니다. 하나라도 실제 결과가 다르거나 요청이 실패하면 통과로 바꾸지 않습니다.
5. **「개인정보 제외 기록 JSON 복사」**를 눌러 결과를 별도 비공개 점검 노트에 보존할 수 있습니다. 자동으로 서버·GitHub·브라우저 저장소에 기록하지 않습니다. 실제 메모 본문, 응답 쿠키, 액세스 토큰, 이메일, 계정 ID는 복사·캡처·커밋하지 않습니다.

## 별도 실행이 필요한 단계

1~11단계를 표 한곳에 두되, 실행 조건이 다른 행은 그대로 **미실행**입니다.

- 3단계: 로그인 세션의 유효성 별도 확인. `POST /api/auth`의 `status` 응답에 계정 정보가 들어 있으므로 화면에 원본을 저장하지 않습니다.
- 4단계: 본인 소유 메모 단건 허용과 **시험 계정 B → A의 타인 자료 거부**는 서로 다른 시험 계정이 필요합니다. 실제 메모 ID는 비공개로 유지합니다.
- 5단계: Supabase 원본 Data API에 대한 비인가 조회 및 현행 GRANT/RLS 검증은 따로 수행해야 합니다.
- 6~8단계: 판정기 `allow`, `deny`, `step_up`과 구역 분리는 현재 **가상 판정기/제공 엔진 계약** 기반입니다. 로컬 `decider:test`, `fixture:7`의 통과를 운영 API 실측으로 적지 않습니다. 반 공지 API도 현재 운영 구현이 아닙니다.
- 9단계: `propose_revocation`은 **회수 제안**입니다. 실제 집행·세션 차단이 확인될 때까지 운영 회수 성공으로 적지 않습니다.
- 10단계: 비공개 로컬 정책/가상 메모 복구는 운영 Supabase 메모 복구가 아닙니다. `restore --confirm` 또는 운영 `/api/restore`를 재실행하지 않습니다.
- 11단계: 로그인했지만 미승인된 별도 기기가 `/api/notes`에서 HTTP 403을 받는지 확인하려면 **별도의 미승인 기기**가 필요합니다. 쿠키를 생략한 HTTP 401을 미승인 기기의 HTTP 403이라고 바꿔 쓰지 않습니다.

기존 `docs/DECIDER_REQUEST.md`, `docs/DETECT_EVENTS.md`의 계약, 이전 1~11단계 README 기록과 실제 운영 결과를 대조하되, 이번 읽기 전용 5건만의 결과를 1~11단계 전체 또는 41종 총공세 통과라고 표현하지 않습니다.
