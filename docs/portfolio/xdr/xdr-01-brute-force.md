# XDR-01 | 무차별 로그인 공격 탐지

**기록 출처:** [기존 루트 README — 보너스 xdr-01 저장점](../../../README.md) 및 과제 진행 중 확인된 검증 요약  
**저장점:** `f6f06e0` (2026-10-30)  
**문장 상태:** 당시 작성된 3줄 기록의 **완전한 원문은 확인되지 않았습니다.** 아래 제작별 기록은 확인 가능한 사실로 새로 정리한 요약입니다.

## 과제 개요

실습용 Wazuh 형식 로그인 경보를 읽고 MITRE ATT&CK T1110 계열의 무차별 대입 시도를 `block`·`alert`·`record`로 분류했습니다. 임시 거부 규칙은 로컬 실험용으로 준비했습니다.

## 제작 단계별 3줄 요약 — 당시 원문 아님

### 제작 1 — 경보 읽기

- **문제:** Wazuh 형식의 로그인 경보에서 필요한 정보만 추출해야 했습니다.
- **해결 방법:** 시각·출발 IP·계정·규칙 수준·설명을 읽는 독립 모듈 `read-alerts.mjs`를 구성했습니다.
- **검증:** 가상 경보 28건에 대해 추출 결과 28줄과 JavaScript 문법 검사 통과를 확인했습니다.

### 제작 2 — 공격 패턴 목록

- **문제:** 반복 로그인 실패가 비밀번호 추측인지 여러 계정 대상 스프레이인지 구분할 근거가 필요했습니다.
- **해결 방법:** MITRE ATT&CK T1110.001 및 T1110.003을 바탕으로 `patterns.json`에 두 패턴과 한 줄씩의 근거를 정리했습니다.
- **검증:** 패턴 2개와 각 패턴의 근거 존재를 확인했습니다.

### 제작 3 — 독립 판단 모듈

- **문제:** 명확한 공격, 애매한 경보, 정상 이벤트를 분리해야 했습니다.
- **해결 방법:** T1110 계열 패턴과 확신도를 이용하는 독립형 `decide(alert)` 함수를 만들었습니다.
- **검증:** 28건을 `block` 10건, `alert` 9건, `record` 9건으로 분류했으며, `decide.mjs`의 독립 실행 구조를 확인했습니다.

### 제작 4 — 알림과 임시 거부 규칙

- **문제:** 탐지 결과를 기반으로 차단 후보를 기록하되 정상 이벤트를 막지 않고 만료 조건을 부여해야 했습니다.
- **해결 방법:** `respond.mjs`에서 근거 경보 ID와 15분 만료 시각이 있는 임시 거부 규칙과 알림 로그를 만들었습니다.
- **검증:** 로컬 규칙 검사에서 공격은 `deny`, 정상·만료는 `continue`였고, 규칙은 `staged_only`로 표시됐습니다.

### 제작 5 — 시험 경보

- **문제:** 정상 이벤트를 잘못 차단하지 않으면서 경보를 분류하는지 확인해야 했습니다.
- **해결 방법:** `npm.cmd run xdr:run -- brute-force`로 원본 가상 경보 묶음을 다시 처리했습니다.
- **검증:** `result.json`의 집계는 `block` 10건, `alert` 9건, `record` 9건이며 정상 이벤트 `bf-20`~`bf-28` 오차단은 0건이었습니다.
