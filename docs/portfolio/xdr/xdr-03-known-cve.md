# XDR-03 | 알려진 취약점 악용 탐지

**작업 범위:** 제작 1 — 경보 읽기 · 제작 2 — 알려진 취약점 패턴 목록 (2026-11-06)
**기록 출처:** [XDR 입력 계약](../../../xdr/README.md), [제공된 시험 경보](../../../xdr/fixtures/known-cve.json), 제작 1 구현 코드 및 테스트
**상태:** 제작 1 로컬 4/4 통과·원본 24건/출력 24줄 확인(사용자 제공 실행 로그), 커밋 `1a12c46`. 제작 2 패턴 목록 작성·로컬 확인 대기. 제작 3~5는 미진행.

## 과제 목표

Wazuh 형식의 교육용 경보 중 알려진 CVE 악용과 관련된 요청을 분석할 준비를 합니다. 첫 단계에서는 판정하지 않고, 입력 원본을 변경하지 않은 채 시각·출발 IP·계정·규칙 수준·설명 **다섯 필드만** 읽습니다. 설명 속 인증 정보처럼 보이는 값은 출력에서 가립니다.

## 제작 1 — 경보 읽기

- **문제:** 한 경보의 여러 속성을 그대로 출력하면 개인정보·비밀값처럼 보이는 정보가 노출될 수 있고, 계정이 없는 경보가 누락될 수 있습니다.
- **해결:** 독립 실행 파일 `xdr/known-cve/read-alerts.mjs`를 만들고 다섯 필드만 정규화했습니다. 계정 등 없는 정보는 `null`로 표시하고, 설명에 있는 토큰·비밀번호 형식 등은 마스킹합니다. `decide.mjs`, 기존 ZTNA 정책, 원본 경보 파일은 변경하지 않습니다.
- **검증:** 원본 파일의 경보 개수(24건)와 추출한 줄 수가 같고 파일 해시가 유지되는지 검사하는 `test/xdr03-read-alerts.test.mjs`를 추가했습니다. 사용자 PC에서 `node --test test/xdr03-read-alerts.test.mjs` **4/4 통과**, 실행 출력 **24줄**을 확인했습니다. 테스트는 원본 보존과 민감값 마스킹을 포함합니다.

## 내가 판단한 것과 배운 점

- **설계 선택:** 첫 제작에서는 분류 규칙을 구현하지 않고 읽기와 판정을 분리했습니다. 추후 `decide(alert)`는 심판 격리 환경에서 단독 실행해야 하므로 읽기 모듈을 `import`하지 않도록 합니다.
- **학습 개념:** 로그 정규화는 입력 형식에서 필요한 항목만 일정하게 뽑아 분석 가능한 구조로 만드는 과정입니다. 비밀값 마스킹과 입력 검증은 이 단계의 별도 안전 요구사항입니다.
- **기여 기록:** 사용자 요청의 다섯 필드·원본 보존·민감값 제외 조건에 맞춰 AI와 함께 구현을 준비했습니다. 별도로 제안한 기능은 확인되지 않았으므로 독자 아이디어로 적지 않습니다.

## 제작 2 — 알려진 취약점 악용 패턴 목록

- **문제:** 취약점 이름 검색이나 점검 도구의 흔적만으로 공격을 차단하면 정상적인 문서 열람·수업용 점검까지 오차단할 수 있습니다.
- **해결:** `xdr/known-cve/patterns.json`에 CVE-2021-44228의 원격 JNDI 조회 형태를 **요청 머리글**과 **URL 인자**로 구분하고, **점검 도구 흔적**은 약한 조사 신호로 분리했습니다. 세 패턴마다 이름·찾는 조건·한 줄 근거·공식 출처를 기록했습니다.
- **검증:** `test/xdr03-patterns.test.mjs`에서 패턴 3개, 각 근거 한 줄, 공식 근거 링크, 실제 Wazuh 필드 및 자동 차단 방지 문구를 확인하도록 했습니다. **이 문서 작성 시 사용자 PC의 테스트 결과는 아직 확인 전**입니다.

### 판단 기준과 근거

| 패턴 | 참조할 경보 필드 | 근거 강도 |
|---|---|---|
| JNDI 머리글 조회 | `data.useragent`, `rule.description` | 완전한 원격 조회 구문이 확인되면 강한 악용 신호 |
| JNDI URL 인자 조회 | `data.url`, `rule.description` | 완전한 원격 조회 구문이 확인되면 강한 악용 신호 |
| 취약점 점검 도구 흔적 | `rule.description` | 단독으로는 자동 차단하지 않는 조사 신호 |

**참고:** [NVD CVE-2021-44228](https://nvd.nist.gov/vuln/detail/CVE-2021-44228) · [MITRE ATT&CK T1190](https://attack.mitre.org/techniques/T1190/). 실제 악용 성공, 운영 ZTNA 차단이나 이번 제작의 심판 점수는 확인하지 않았습니다. 해당 패턴은 다음 제작의 판단 기준 자료일 뿐, 아직 `decide.mjs`에 반영되지 않았습니다.

### 포트폴리오 3줄 — 제작 2

- **문제:** 경보에 CVE 이름이나 점검 흔적만 나타나도 공격으로 오판할 위험이 있었습니다.
- **해결:** 원격 JNDI 조회 구문(머리글·URL 인자)과 약한 점검 도구 흔적을 구분하고, 각 패턴에 공식 근거를 한 줄씩 남겼습니다.
- **검증:** 패턴 개수·근거 한 줄·공식 출처를 확인하는 테스트를 작성했습니다. 실제 PC 실행 결과는 확인 후 갱신할 예정입니다.

## 재현 및 한계

```powershell
node --test test/xdr03-read-alerts.test.mjs test/xdr03-patterns.test.mjs
node xdr/known-cve/read-alerts.mjs
```

정상이라면 24개 경보에 대한 JSON 출력이 **24줄**이어야 합니다. 이 결과는 **경보 읽기 확인**이며, 악용 차단·오탐률·운영 ZTNA 연동이나 공식 심판 점수를 뜻하지 않습니다. 실제 운영 로그가 아닌 수업용 경보입니다.
