# XDR-03 | 알려진 취약점 악용 탐지

**작업 범위:** 제작 1 — 경보 읽기 (2026-11-06)
**기록 출처:** [XDR 입력 계약](../../../xdr/README.md), [제공된 시험 경보](../../../xdr/fixtures/known-cve.json), 제작 1 구현 코드 및 테스트
**상태:** 제작 1 구현. 로컬 PC 검사·공식 심판 평가는 별도 확인 필요. 제작 2~5는 아직 미진행.

## 과제 목표

Wazuh 형식의 교육용 경보 중 알려진 CVE 악용과 관련된 요청을 분석할 준비를 합니다. 첫 단계에서는 판정하지 않고, 입력 원본을 변경하지 않은 채 시각·출발 IP·계정·규칙 수준·설명 **다섯 필드만** 읽습니다. 설명 속 인증 정보처럼 보이는 값은 출력에서 가립니다.

## 제작 1 — 경보 읽기

- **문제:** 한 경보의 여러 속성을 그대로 출력하면 개인정보·비밀값처럼 보이는 정보가 노출될 수 있고, 계정이 없는 경보가 누락될 수 있습니다.
- **해결:** 독립 실행 파일 `xdr/known-cve/read-alerts.mjs`를 만들고 다섯 필드만 정규화했습니다. 계정 등 없는 정보는 `null`로 표시하고, 설명에 있는 토큰·비밀번호 형식 등은 마스킹합니다. `decide.mjs`, 기존 ZTNA 정책, 원본 경보 파일은 변경하지 않습니다.
- **검증:** 원본 파일의 경보 개수(24건)와 추출한 줄 수가 같고 파일 해시가 유지되는지 검사하는 `test/xdr03-read-alerts.test.mjs`를 추가했습니다. **사용자 PC 실행 결과는 아직 확인 전**이므로 통과로 기록하지 않습니다.

## 내가 판단한 것과 배운 점

- **설계 선택:** 첫 제작에서는 분류 규칙을 구현하지 않고 읽기와 판정을 분리했습니다. 추후 `decide(alert)`는 심판 격리 환경에서 단독 실행해야 하므로 읽기 모듈을 `import`하지 않도록 합니다.
- **학습 개념:** 로그 정규화는 입력 형식에서 필요한 항목만 일정하게 뽑아 분석 가능한 구조로 만드는 과정입니다. 비밀값 마스킹과 입력 검증은 이 단계의 별도 안전 요구사항입니다.
- **기여 기록:** 사용자 요청의 다섯 필드·원본 보존·민감값 제외 조건에 맞춰 AI와 함께 구현을 준비했습니다. 별도로 제안한 기능은 확인되지 않았으므로 독자 아이디어로 적지 않습니다.

## 재현 및 한계

```powershell
node --test test/xdr03-read-alerts.test.mjs
node xdr/known-cve/read-alerts.mjs
```

정상이라면 24개 경보에 대한 JSON 출력이 **24줄**이어야 합니다. 이 결과는 **경보 읽기 확인**이며, 악용 차단·오탐률·운영 ZTNA 연동이나 공식 심판 점수를 뜻하지 않습니다. 실제 운영 로그가 아닌 수업용 경보입니다.
