# XDR-03 | 알려진 취약점 악용 탐지

**작업 범위:** 제작 1 — 경보 읽기 · 제작 2 — 패턴 목록 · 제작 3 — 독립 판단 · 제작 4 — 임시 거부·알림 연결 (2026-11-06)
**기록 출처:** [XDR 입력 계약](../../../xdr/README.md), [제공된 시험 경보](../../../xdr/fixtures/known-cve.json), 제작 1~3 구현 코드·테스트와 사용자 제공 로컬 결과
**상태:** 제작 1~2 로컬 7/7 통과(커밋 `1a12c46`, `bcee2ce`). 제작 3 로컬 12/12 통과(8 block·8 alert·8 record), 커밋 `b301fd5`(사용자 제공 로그). 제작 4 구현·로컬 PC 검증 대기. 제작 5 미진행.

## 과제 목표

Wazuh 형식의 교육용 경보 중 알려진 CVE 악용과 관련된 요청을 분석할 준비를 합니다. 첫 단계에서는 판정하지 않고, 입력 원본을 변경하지 않은 채 시각·출발 IP·계정·규칙 수준·설명 **다섯 필드만** 읽습니다. 설명 속 인증 정보처럼 보이는 값은 출력에서 가립니다.

## 제작 1 — 경보 읽기

- **문제:** 한 경보의 여러 속성을 그대로 출력하면 개인정보·비밀값처럼 보이는 정보가 노출될 수 있고, 계정이 없는 경보가 누락될 수 있습니다.
- **해결:** 독립 실행 파일 `xdr/known-cve/read-alerts.mjs`를 만들고 다섯 필드만 정규화했습니다. 계정 등 없는 정보는 `null`로 표시하고, 설명에 있는 토큰·비밀번호 형식 등은 마스킹합니다. `decide.mjs`, 기존 ZTNA 정책, 원본 경보 파일은 변경하지 않습니다.
- **검증:** 원본 파일의 경보 개수(24건)와 추출한 줄 수가 같고 파일 해시가 유지되는지 검사하는 `test/xdr03-read-alerts.test.mjs`를 추가했습니다. 사용자 PC에서 `node --test test/xdr03-read-alerts.test.mjs` **4/4 통과**, 실행 출력 **24줄**을 확인했습니다. 테스트는 원본 보존과 민감값 마스킹을 포함합니다.

## 내가 판단한 것과 배운 점

- **설계 선택:** 첫 제작에서는 분류 규칙을 구현하지 않고 읽기와 판정을 분리했습니다. 추후 `decide(alert)`는 심판 격리 환경에서 단독 실행해야 하므로 읽기 모듈을 `import`하지 않도록 합니다.
- **학습 개념:** 로그 정규화는 입력 형식에서 필요한 항목만 일정하게 뽑아 분석 가능한 구조로 만드는 과정입니다. 비밀값 마스킹과 입력 검증은 이 단계의 별도 안전 요구사항입니다.
- **기여 기록:** 사용자 요청의 다섯 필드·원본 보존·민감값 제외 조건에 맞춰 AI와 함께 구현을 준비했습니다. 별도로 제안한 기능은 확인되지 않았으므로 독자 아이디어로 적지 않습니다.

## 제작 2 — 알려진 취약점 악용 패턴 목록

- **문제:** 취약점 이름 검색이나 점검 도구의 흔적만으로 공격을 차단하면 정상적인 문서 열람·수업용 점검까지 오차단할 수 있습니다.
- **해결:** `xdr/known-cve/patterns.json`에 CVE-2021-44228의 원격 JNDI 조회 형태를 **요청 머리글**과 **URL 인자**로 구분하고, **점검 도구 흔적**은 약한 조사 신호로 분리했습니다. 세 패턴마다 이름·찾는 조건·한 줄 근거·공식 출처를 기록했습니다.
- **검증:** `test/xdr03-patterns.test.mjs`에서 패턴 3개, 각 근거 한 줄, 공식 근거 링크, 실제 Wazuh 필드 및 자동 차단 방지 문구를 확인하도록 했습니다. 사용자 PC에서 패턴 검사 **3/3 통과**, 제작 1~2 전체 **7/7 통과**를 확인했습니다(사용자 제공 로그).

### 판단 기준과 근거

| 패턴 | 참조할 경보 필드 | 근거 강도 |
|---|---|---|
| JNDI 머리글 조회 | `data.useragent`, `rule.description` | 완전한 원격 조회 구문이 확인되면 강한 악용 신호 |
| JNDI URL 인자 조회 | `data.url`, `rule.description` | 완전한 원격 조회 구문이 확인되면 강한 악용 신호 |
| 취약점 점검 도구 흔적 | `rule.description` | 단독으로는 자동 차단하지 않는 조사 신호 |

**참고:** [NVD CVE-2021-44228](https://nvd.nist.gov/vuln/detail/CVE-2021-44228) · [MITRE ATT&CK T1190](https://attack.mitre.org/techniques/T1190/). 실제 악용 성공, 운영 ZTNA 차단이나 이번 제작의 심판 점수는 확인하지 않았습니다. 해당 세 패턴은 제작 3의 독립 `decide.mjs` 상수로 옮겼습니다.

### 포트폴리오 3줄 — 제작 2

- **문제:** 경보에 CVE 이름이나 점검 흔적만 나타나도 공격으로 오판할 위험이 있었습니다.
- **해결:** 원격 JNDI 조회 구문(머리글·URL 인자)과 약한 점검 도구 흔적을 구분하고, 각 패턴에 공식 근거를 한 줄씩 남겼습니다.
- **검증:** 패턴 개수·근거 한 줄·공식 출처 검사 **3/3 통과**, 제작 1~2 누적 **7/7 통과**를 확인했습니다.

## 제작 3 — 독립 판단 모듈

- **문제:** 심판은 인터넷·패키지·파일 접근이 불가능한 격리 환경에서 `decide.mjs`만 호출합니다. CVE 이름·JNDI 단어·불완전한 조회 단서를 완전한 악용 시도와 혼동하면 정상 요청을 차단할 위험이 있습니다.
- **해결:** 제작 2의 세 패턴(id·이름·조건·한 줄 근거·참고 링크)을 `xdr/known-cve/decide.mjs` 상단 상수로 복사하고, **유일한 export `decide(alert)`**가 Wazuh 원본의 `data.useragent`, `data.url`, `rule.description`, `rule.mitre`, `rule.level`을 검사하도록 만들었습니다. 완전한 JNDI 원격 조회 구문과 높은 경보 수준 및 T1190/CVE 맥락이 함께 있으면 `confidence ≥ 0.85`로 차단합니다. 불완전한 단서나 점검 유사 흔적은 `0.5~0.84` 경고, 일반 이벤트는 그 미만 기록으로 둡니다.
- **검증:** `test/xdr03-decide.test.mjs`에서 판단 결과 세 필드·0~1 확신도·세 기준값·한 줄 패턴명·의심/정상 구분·원본 불변·격리 실행 제약을 검사합니다. 사용자 PC에서 제작 1~3 테스트 **12/12 통과**했고, 교육용 원본 24건은 **block 8·alert 8·record 8**로 분류됐습니다(사용자 제공 로그).

### 설계 판단과 학습 기록

- **판단 이유:** 실제 원격 조회 구문이 있는지 먼저 확인하고, Wazuh T1190 또는 CVE 설명과 높은 규칙 수준으로 교차 확인한 경우에만 자동 차단 판단을 반환합니다. CVE 검색, 단어 하나, 학습용 문서 접근 등은 자동 차단하지 않습니다.
- **애매한 경보 처리:** 제작 2의 세 번째 패턴명은 추가 조사할 약한 신호의 분류명이지 실제 점검 도구 실행이나 침해 성공의 증명이 아닙니다. 조사 분류를 침해 확정으로 과장하지 않습니다.
- **보안 운영 학습:** 탐지 결과의 `block`은 XDR 분류 결과이며, 실제 방화벽·ZTNA의 IP 차단 또는 세션 회수 명령 집행과 구분합니다. `reason`은 일치 또는 관련 패턴명만 한 줄로 남기고 원본 IP·URL·토큰을 되돌려 주지 않습니다.
- **개별 기여 범위:** 사용자 공식 프롬프트에 따라 AI와 함께 분류 기준·독립 실행 제약을 구현한 단계입니다. 운영 적용과 독자적인 새 공격 패턴 발견을 주장하지 않습니다.

### 포트폴리오 3줄 — 제작 3

- **문제:** 격리 심판이 단독 실행하는 파일에서 완전한 악용 시도와 검색·점검 단서를 구분해야 했습니다.
- **해결:** 패턴 3개를 상수로 내장하고, `decide(alert)`가 0.85/0.50 임계값으로 `block`·`alert`·`record`를 반환하도록 구현했습니다.
- **검증:** 격리 실행·패턴 일치·정상 오차단·반환 계약의 단위 시험을 작성했습니다. 사용자 PC의 교육용 24건 **8·8·8 분류** 및 누적 테스트 **12/12 통과**를 확인했습니다.

## 제작 4 — 임시 거부 규칙과 알림 기록 연결

- **문제:** `decide(alert)`의 `block` 반환만으로는 실제 접근 거부가 이루어지지 않습니다. 또한 출발 IP를 그대로 막으면 같은 주소를 공유하는 정상 사용자가 오차단될 위험이 있습니다.
- **해결:** 독립된 `xdr/known-cve/respond.mjs`에서 판단 결과를 다시 확인해 **명확한 JNDI 악용 경보(`block`, 확신도 0.85 이상)**에 대해서만 15분 만료의 임시 IP 거부 규칙을 만듭니다. 규칙에는 첫 경보를 기준으로 한 ID, 근거 경보 ID 목록, 시작·만료 시각, 패턴 이름을 남깁니다. 같은 IP에서 정상·애매한 사건이 ±15분 내 확인되면 자동 IP 거부를 보류합니다. 알림은 원본 IP·계정·URL 없이 `xdr/alerts.log`에 JSON 한 줄씩 추가합니다.
- **검증:** `test/xdr03-respond.test.mjs`에서 명확한 공격만 규칙에 등록하는지, 정상 요청의 기존 판정 계속 진행, 만료 후 거부 해제, 공유 IP 혼합 사건 보호, 비밀값 없는 로그 누적을 검사합니다. **사용자 PC 실행 결과는 아직 확인 전**이며, 규칙·로그는 로컬 실습 결과입니다.

### 설계 선택과 보안 운영 학습

- **판정과 집행의 분리:** `decide.mjs`는 순수 판단만 반환하고, 파일 쓰기와 거부 규칙 생성은 `respond.mjs`에서만 수행합니다. 심판이 단일 파일로 실행하는 `decide.mjs`의 독립성을 유지했습니다.
- **보수적인 차단 조건:** 정상·경고 경보는 거부 규칙을 생성하지 않습니다. 같은 IP의 혼합 사건도 보류하지만, 관측하지 못한 공유 IP 사용자까지 식별하는 기술은 아니므로 오차단 가능성을 0으로 주장하지 않습니다.
- **연동 한계:** 기존 `docs/DECIDER_REQUEST.md`의 18개 ZTNA 요청 필드에는 검증된 출발 IP가 없습니다. 따라서 `checkTrustedSourceIp()`는 **신뢰된 출발 IP가 공급된다는 가정하에 로컬에서 거부/계속 진행을 재현하는 연결 지점**일 뿐, 실제 ALEPH SDP 엔진의 자동 거부 규칙이 아닙니다. `continue`는 기존 ZTNA 판정을 계속한다는 뜻이며 강제 허용을 의미하지 않습니다.
- **운영 개념:** 만료 시각(TTL)은 일시적인 공격 신호를 영구 차단하지 않게 하는 통제이고, 근거 경보 번호는 나중에 왜 거부했는지 추적하는 감사 근거입니다. 본 단계는 사용자 공식 요청에 따른 구현이며 추가 아이디어를 임의로 개인 기여로 주장하지 않습니다.

### 포트폴리오 3줄 — 제작 4

- **문제:** XDR의 차단 판단을 규칙으로 연결하되, 정상·공유 IP 이용자를 잘못 막지 않아야 했습니다.
- **해결:** 확신도가 높은 `block` 경보만 근거 번호·만료 시각이 있는 15분 임시 거부 규칙으로 만들고 알림을 별도 로그에 누적했습니다.
- **검증:** 공격 거부·정상 계속 진행·만료 해제·혼합 IP 보호·알림 누적을 검사하는 테스트를 추가했습니다. 사용자 PC 검증 결과 확인 대기입니다.

## 재현 및 한계

```powershell
node --test test/xdr03-read-alerts.test.mjs test/xdr03-patterns.test.mjs test/xdr03-decide.test.mjs test/xdr03-respond.test.mjs
node xdr/known-cve/read-alerts.mjs
node xdr/known-cve/respond.mjs
```

정상이라면 24개 경보에 대한 JSON 출력이 **24줄**이어야 합니다. 이 결과는 **경보 읽기 확인**이며, 악용 차단·오탐률·운영 ZTNA 연동이나 공식 심판 점수를 뜻하지 않습니다. 실제 운영 로그가 아닌 수업용 경보입니다.
