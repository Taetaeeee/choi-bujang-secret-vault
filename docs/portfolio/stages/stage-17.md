## 과제와 관측 범위

17단계는 **AI 앱 연결 확인**과 **선택한 보안 사건에 대한 실제 AI 설명 실행**을 혼동하지 않도록 표시하는 단계입니다. 13~16단계 기능을 유지하며 학생 화면에서 연결 점검의 대기·진행·성공·실패와 오류별 안내, 사건 설명의 기본 결과 표시를 구현했습니다.

- **계정 연결:** ALEPH 계정과 로컬 보안 Agent의 연결을 먼저 확인합니다. 이 결과만으로 AI 앱 승인 또는 모델 이용 권한이 확인된 것은 아닙니다.
- **AI 앱 연결:** 별도 확인 번호와 포털 승인 과정을 거쳐 연결합니다. 승인과 모델 점검은 서로 다른 절차입니다.
- **모델 점검:** `audienceAuthorization`의 `test`(시험 점검)와 `verified`(해당 시각의 앱 권한 확인 후 점검)를 구분하며, `modelCount`와 `checkedAt`을 표시합니다. 모델 목록 응답만으로 사건 설명이 실행된 것은 아닙니다.
- **사건 설명:** `renderExplanation`은 선택 사건의 설명 성공·실패를 표시하는 **17단계 기초 구현**입니다. 상세 근거 연결과 해석 확장은 후속 18단계 범위입니다.
- **운영 경계:** 비밀번호·토큰·API 키를 브라우저에 입력하거나 학생 코드에서 직접 AI 공급자에 연결하지 않습니다. 제공 서버·UI가 전달한 결과를 표시합니다.

## 문제 → 해결 방법

- **문제:** 앱 연결 완료, 모델 응답 점검, 실제 사건 설명 성공이 같은 의미로 보이면 AI가 사건을 분석하지 않았는데도 분석한 것처럼 오해할 수 있습니다. 또한 인증·권한·사용량·시간 초과·취소 오류를 일괄 실패로 보여 주거나, 재점검 이후 이전 성공/오류를 남기는 문제를 방지해야 했습니다.
- **입력 계약 ①:** `renderAiConnection({ status, mode, data?, error?, checkedAt, explanationAccepted })`. `status`는 `idle`·`loading`·`ok`·`error`이고, 점검 `data`에는 `transportChecked`, `audienceAuthorization`, `modelCount`, `help`가 전달됩니다.
- **입력 계약 ②:** `renderExplanation({ event, explanation, checkedAt })`. 성공 시 `event.id`, `explanation.data.summary`를 표시하고 바깥 요소에 `data-student-explanation-event=event.id`를 붙입니다. 실패 시에는 이 성공 표식을 붙이지 않습니다.
- **학생 코드 수정 범위:** `on-client/student/extension.mjs`의 **`renderAiConnection`과 `renderExplanation` 기초**를 구현했습니다. 기존 `renderIdentity`, `renderDecision`, `renderEvents`, `renderStatus`는 보존했습니다. `document.createElement`와 `textContent`를 사용하며 자동 AI 호출·자동 재시도·보안 조치를 추가하지 않았습니다.
- **상태 분리:** `idle`은 'AI 연결 점검 전', `loading`은 'AI 연결 점검 중', `ok`는 시험/검증된 연결 상태·모델 수·시각, `error`는 오류 코드·안전한 안내 문구를 보여 줍니다. 성공 화면에도 **사건 설명 미실행**을 명시합니다.
- **원인별 오류 안내:** 인증·접근 제한, 권한 준비·확인 불가, 사용량·한도, 이용 시간, 요청 제한·시간 초과·네트워크, 취소, 모델 없음에 대해 서로 다른 안내 방향을 적용합니다. 안전한 `error.code`·`error.message`만 표시하고 원문 오류/비밀값 의심 문자열은 제한합니다.
- **이전 결과 제거:** 입력이 새로 들어올 때 DOM을 새로 반환하여 재점검 성공 후 과거 오류를 남기지 않으며, `idle` 복귀 때 과거 성공 표시를 제거합니다. 취소·설명 실패는 완료/성공으로 표시하지 않습니다. 늦게 온 서버 응답 무효화 자체는 제공 UI의 역할입니다.
- **사건 설명의 기본 표시:** 선택 사건이 없으면 선택 안내, 설명 요청 중이면 진행 표시, 설명 실패면 안전한 코드·메시지와 원래 보안 기록 유지 안내, 성공이면 사건 ID·AI 요약을 표시합니다. 설명 출력은 참고용이며 원천 조치를 실행하지 않습니다.
- **시작 틀 업데이트:** AI 앱 연결 과정에서 사용하던 시작 틀 `0.2.14`를 공식 **`0.2.21` 보존 업데이트 스크립트**로 교체했습니다. 이 업데이트는 **학생 함수 구현과 별개의 제공 코드 갱신**이며 학생 영역과 Git 기록을 보존하도록 수행했습니다. 제출 커밋에는 시작 틀 갱신 파일 38개와 학생 파일 1개, 총 39개가 포함됩니다.

## 선택과 학습

연결에 성공했다는 사실과 실제 AI가 특정 보안 사건을 분석했다는 사실을 분리해야 합니다. 이 구분을 유지하면 권한 미설정·인증 실패·한도 초과·취소를 정상 결과로 오인하지 않으며, 재점검 뒤 과거 결과를 현재 결과처럼 보여 주는 실수도 줄일 수 있습니다. 제공 UI의 연결/모델 점검과 학생 함수의 결과 표현은 책임 범위가 다르다는 점도 확인했습니다.

## 포트폴리오 3줄 요약 — 문제 → 해결 → 검증

- **문제:** AI 앱 승인, 모델 목록 확인, 실제 보안 사건 설명을 같은 성공으로 보여 주거나 연결 실패 후 오래된 결과를 남길 위험이 있었습니다.
- **해결:** `renderAiConnection`에 상태·권한·모델 수·시각 및 오류별 안내를 구현하고, `renderExplanation`에 사건별 요약·실패 분리와 성공 표식을 구현했습니다. 공식 시작 틀을 보존 업데이트 방식으로 0.2.21까지 갱신했습니다.
- **검증:** 연결 오류와 권한 준비 안내를 실제 화면에서 확인한 뒤 `verified`·모델 1개 응답을 확인했으며, **2026-11-10 17:39 접수된 공식 필수 9/9 통과** 결과를 받았습니다. 실제 로컬 SDP 사건 설명 실행은 미확인입니다.
