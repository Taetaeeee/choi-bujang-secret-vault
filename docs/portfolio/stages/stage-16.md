## 과제와 관측 범위

조회 중·조회 성공·빈 목록·조회 실패를 혼동하지 않고 기기·세션·알림을 안내하며, 도움 요청에 필요한 진단 정보만 복사하도록 구성했습니다. 지원하지 않는 조치를 실제 실행하는 것처럼 보여 주지 않는 것도 핵심 요구사항입니다.

- 기기 범위: 본인 이름으로 등록되고 회수되지 않은 기기 **최대 100개**. 실제 전체 조직 기기 목록이 아닙니다.
- 세션 범위: **현재 검증된 연결 한 개**. 과거 전체 로그인 세션 이력이 아닙니다.
- 오류·확인 범위: 제공 화면이 조회·검증한 자료를 학생 함수에 전달합니다. 상태 화면이 별도 API를 호출해 확장 조회하지 않습니다.
- 원천 조치: 실제 목록의 `supportedActions`는 빈 배열이므로, 미지원 조치 버튼은 실제 사건 화면에서 등장하지 않는 것이 정상입니다. 자동 확인에서 조치 식별자를 전달할 때만 비활성 안내 버튼을 보여 줍니다.

## 문제 → 해결 방법

- **문제:** 기기·세션이 없는 상태와 네트워크/엔진 연결 실패를 같은 메시지로 표시하면 사용자가 장애를 놓칠 수 있습니다. 서버 진단 자료를 무분별하게 복사하거나, 조치 버튼을 활성화하면 불필요한 노출 또는 조치 성공에 대한 오해가 발생합니다.
- **입력 계약:** `renderStatus({ devices, sessions, notifications, diagnostics, mode })`. `devices`, `sessions`, `diagnostics`는 `{ status, mode, data?, error? }`이며, `notifications`는 `{resource,code,message}` 배열입니다. 제공 앱의 `studentData('status')`가 전달하고, 진단 API 호출은 제공 화면이 담당합니다.
- **수정 범위:** `on-client/student/extension.mjs`의 `renderStatus`를 구현하고 기존 `renderEvents`의 **기록 상세 생성부**에만 미지원 안내를 추가했습니다. 기존 13~15단계의 정렬·필터·상세 기능 및 다른 학생 함수, 서버·`public/app.js`·판정·인증 설정은 보존했습니다. 표시에는 `document.createElement`와 `textContent`를 사용했습니다.
- **기기·세션:** 각각 `loading`, `ok`(자료 있음), `ok`(빈 배열), `error`, 미조회 상태를 구분합니다. 기기는 `label`·원래 `status`와 한국어 설명, 세션은 `id`·원래 `status`와 한국어 설명을 함께 표시합니다. 세션 목록을 과거 전체 이력으로 표현하지 않습니다.
- **수동 재시도:** 실패 시 대상 자료와 메시지를 보여 주고 시간 초과 여부를 구분합니다. 제공 UI 위쪽 **`다시 불러오기`** 버튼을 사용자가 직접 누르도록 안내하며, 학생 코드에 자동 재요청이나 API 호출을 추가하지 않았습니다. 새로운 렌더링은 이전 실패 문구를 현재 성공 상태에 남기지 않도록 DOM을 새로 구성합니다.
- **알림:** `notifications` 배열마다 `resource`, `code`, `message`를 나누어 표시합니다. 알림이 비어 있으면 `주의할 알림이 없습니다.`라고 안내합니다. 화면에 안전하게 표시할 수 없는 긴 값·비밀값 의심 문자열은 제한합니다.
- **진단 정보:** 서버가 반환한 진단 결과 중 **`requestId`, `component`, `version`, `checkedAt`, `engine.mode`, `engine.code`**만 화면에 표시하고, 학생 영역의 정확한 이름 **`도움정보 복사`** 버튼을 클릭할 때만 이 필드를 포함한 JSON을 클립보드에 기록합니다. 원본 진단 응답의 `meta`, `ai`, 그 밖의 필드는 복사하지 않습니다. 진단 미조회·로딩·실패 상태에는 복사 버튼이 비활성입니다.
- **미지원 조치:** 기존 15단계의 `data-student-event-detail` 안에서 `supportedActions`가 비어 있지 않을 때만 `<action> 미지원` 형태의 **비활성 버튼**과 조치 미연결 설명을 추가합니다. 실제 조치 요청은 전송하지 않습니다. 조치 실행 성공을 표시하지 않습니다.

## 포트폴리오 3줄 요약 — 문제 → 해결 → 검증

- **문제:** 기기·세션 조회 실패를 정상적인 빈 목록과 구분하고, 장애 시 안전한 도움정보와 재시도 방법을 제공해야 했습니다.
- **해결:** `renderStatus`에 상태별 메시지·알림·진단 허용 필드 복사 버튼을 구현하고, `renderEvents` 상세에 원천 미지원 조치의 비활성 안내를 추가했습니다.
- **검증:** 문법·Git 범위 검사, 브라우저의 연결 실패 메시지·진단 표시, 학생 버튼의 6개 필드 클립보드 복사를 확인하고, **2026-11-09 14:54 접수된 공식 7/7 통과** 결과를 받았습니다. 연결 복구 후 재조회 및 실제 조치 입력 사례는 미확인입니다.
