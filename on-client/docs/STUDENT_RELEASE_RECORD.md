## 5. 데이터 보존·백업·복원 계획과 제한

1. **원본 작업·Git 이력 보존:** 기존 `choi-bujang-secret-vault`는 `main`에서 변경 0건 상태로 두고, 재현 폴더를 새 경로에 만듭니다. 제출 이후에도 포트폴리오·기존 학생 코드·제공 설정과 Git 커밋 이력을 지우거나 강제 재작성하지 않습니다. 문서는 **원본 저장소에만 신규 추가**하고 detached 검증 복제본은 수정하지 않는 절차로 관리합니다.
2. **Git에 포함되는 것과 제외되는 것:** `.gitignore`가 `artifacts/`, `.env`, `.env.*`, `node_modules/` 등을 제외합니다. 따라서 GitHub 복제만으로 **로컬 백업·환경변수 파일·실제 사용자 데이터·인증 보관소가 복구되지 않습니다**. `on-client`의 개인 계정 연결 설정은 제공 문서상 프로젝트 밖의 Windows 사용자 폴더에 보관될 수 있습니다. 해당 값을 새 폴더로 복사하거나 Git에 넣지 않습니다.
3. **학생 가상 데이터·백업:** 루트 `README.md`의 **10단계 로컬 연습**은 `artifacts/stage10/private/`의 비공개 가상 메모 사본·SHA-256 검증 및 `artifacts/stage10/` 내 시험 복원·감사 기록을 사용합니다. Git에 해당 디렉터리가 없다고 운영 데이터가 삭제됐다고 판단하지 않으며, **실제 Supabase 운영 DB의 백업이나 복원 성공으로 해석하지 않습니다**. 기존 비공개 사본은 원본 PC에 보존하고, 필요한 경우 승인된 별도 보관소에서 무결성·소유자·복원 대상을 점검한 후 제한된 테스트 환경에서만 복구합니다.
4. **검증된 사본 복원 원칙:** 기존 `scripts/stage10-restore.mjs` 등 제공 프로젝트의 검증 경로에서 **백업 출처 커밋·SHA-256·대상·승인·감사 이력**을 확인하는 정책을 참고합니다. 복원 시 다른 사용자 자료를 덮어쓰지 않고 감사 기록은 보존/추가 기록합니다. **22단계 재현 중에는 정책 복원·가상 메모 `post`·실제 DB 변경을 실행하지 않았습니다.** 실제 백업의 저장 위치·접근 권한·복구 목표·재해 복구 시험은 **UNV**로 남깁니다.
5. **운영 데이터 복구의 한계:** Supabase 인증 계정·RLS/DB 스냅샷·외부 SDP/XDR·AI 운영 데이터는 이 Git 복제 절차로 복원되지 않습니다. 실제 운영 데이터 백업·복구는 해당 시스템 소유자의 승인된 절차와 별도 검증이 필요합니다. 자격 증명, 사용자 개인정보, 메모 본문, API 키는 문서·캡처·커밋에 포함하지 않습니다.

## 6. 미확인(UNV) 목록 및 다음 검증 기준

- **13~16:** 정상 SDP 연결에서 실제 사용자 신원·등록 기기·접근 판정·XDR 사건과 알림 원천 자료를 가져오는 동작은 확인하지 못했습니다.
- **17~18:** 승인된 CLCO AI 연결, 실제 모델 점검/설명 생성, 근거 ID 대조는 확인하지 못했습니다.
- **19:** 실제 보안 조치 집행 연결은 **미준비**이며, 조치 ACK·효과 재조회·취소 경합을 실운영에서 재현하지 않았습니다.
- **20:** OSV 프로젝트 조회 설정 미완료로 실제 패키지 버전·취약점 ID 대조, 부분 실패/취소/오류 회복의 실제 네트워크 재현은 못 했습니다.
- **21~22:** 제공 문서와 신규 재현 기록은 학생의 실행 증빙이지만, **ALEPH 서버 AI가 새 복제본을 실제 실행한 증거는 아닙니다**. 22단계 공식 평가·제출 커밋의 원문 일관성 및 최종 제출 커밋 자체의 새 환경 확인은 문서 작성 시 **미완료**입니다.

## 7. 최종 제출 커밋 관리·판정 경계

- 이 문서가 추가되면 제출 후보 커밋은 `9eaeed80...`과 달라집니다. **기존 소스가 동일한지** `git diff --name-only 9eaeed80ad8c8d01de292494b07b8162c7d5902b HEAD` 및 전체 `git status`로 확인해야 합니다. 코드 변경이 발생하면 새 제출 커밋에서 로컬 재현을 다시 수행하고 본 문서의 기록을 갱신합니다.
- **제출 전에는** 22단계 문서만 변경했는지, GitHub에 실제 푸시됐는지, 최종 40자리 커밋을 기준으로 새 복제본에서 동일한 실행 진입점과 화면이 유지되는지 확인합니다. **이 항목은 작성 시 미완료**로 둡니다.
- 21·22단계는 ALEPH 과제 화면에 **저장소 주소와 제출할 실제 40자리 커밋 해시를 직접 입력**합니다. 공개 저장소를 비공개로 전환하지 않으며, 비공개 원문 전송 도구는 화면에서 요구할 때 제공 안내만 사용합니다. 공식 접수·판정은 학습자가 결과를 공유한 뒤에만 기록합니다.
- **v1.0 미발행:** 현재 `0.2.21` 검증 중. 외부 조치 집행 연결과 전체 기능 재현 등 안내에 남은 조건을 충족하지 않은 상태에서 버전·운영 인증·완료 점수를 올려 적지 않습니다. 공식 22단계 통과가 곧 실제 운영 보안성 인증 또는 `v1.0` 승인이라는 뜻은 아닙니다.
